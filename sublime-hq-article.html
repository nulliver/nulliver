About this article

A more detailed and informative attempt to tell the history of Sublime Text, showing that, far from being dead, it has stayed alive and successfully overcome challenges with the help of a passionate community of users. In short, this is what I would like the Wikipedia article on Sublime Text to be.

Sublime HQ Pty Ltd is a software company based in Sydney, Australia, that develops the proprietary text editor Sublime Text and the Git client Sublime Merge. The company was founded by Jon Skinner, who began development of Sublime Text in the mid-2000s and released version 1.0 in January 2008.12 Both products are cross-platform, run natively on Windows, macOS and Linux, and are sold under perpetual licenses that include three years of updates.1217

The company is privately owned and has no outside investors; its income comes from the sale of licenses. It has had a small staff throughout its history, numbering three known employees in 2017 and eight in 2022. Much of the surrounding ecosystem, including the bundled language definitions, the Package Control package manager and the LSP client, is developed in public repositories with substantial volunteer participation.

History

Origins and Sublime Text 1 (2007–2010)

The project was announced on a development blog in November 2007. The announcement stated that the founder had left a job at Google to build a text editor and a company around it.1 Sublime Text 1.0, a Windows-only release, followed on 18 January 2008.2 Two blog posts published in April 2008 explained the choice of Python as the editor's extension language.3 Versions 1.2, 1.3 and 1.4 were released between June 2009 and September 2010.1

Sublime Text 2 (2011–2012)

A public alpha of Sublime Text 2, which added support for macOS and Linux, was released on 28 January 2011, followed by a beta in July 2011 and the final 2.0 release on 26 June 2012.4 Package Control, a third-party package manager written by Will Bond, first appeared in 2011.8

Sublime Text 3 (2013–2019)

The Sublime Text 3 beta was announced on 29 January 2013, together with an increase in the license price from US$59 to US$70.5 In the same year the company hired Kari, who handles sales and support and wrote the February 2013 post on upgrade pricing.6 The public beta opened in June 2013.7

Will Bond joined the company in January 2016; the build 3103 release notes welcomed him as the author of Package Control.8 Build 3124 (September 2016) added a menu command to install Package Control.8 The official Discord server opened in early 2017. Sublime Text 3.0 (build 3143) left beta on 13 September 2017, more than four years after the beta began.9 Later 3.x releases introduced the Adaptive theme (October 2017), a JSON-based color scheme format, .sublime-color-scheme (build 3149, October 2017), version 3.1 (May 2018) and version 3.2 (March 2019), which added Git integration and incremental diff markers developed alongside Sublime Merge.1011

Sublime Merge (2018)

On 20 September 2018 the company released Sublime Merge, a Git client built on the same internal application framework as Sublime Text.12 It had been developed without public announcement during 2018, and Sublime Text development builds paused during that period. Sublime Merge introduced the licensing model that the company later applied to Sublime Text: a perpetual license with three years of updates.12 A roadmap post followed in October 2018.13

Sublime Text 4 (2019–2021)

The first public development build of Sublime Text 4, build 4050, was distributed on 12 November 2019 exclusively through the company's Discord server, where testers were asked not to share the download links elsewhere. Development builds required a valid license key, and the beta continued on Discord until the stable release. Sublime Merge 2 was released on 26 May 2020.14

Sublime Text 4 (build 4107) was released on 21 May 2021. Its main features were GPU rendering, multi-selection of tabs, a rewritten context-aware auto-complete system, a Python 3.8 plugin environment alongside the existing Python 3.3 one, built-in TypeScript, JSX and TSX syntax definitions, and native builds for Apple Silicon and Linux ARM64. Support for OS X 10.7 and 10.8 and for Windows XP and Vista was dropped.17 The release moved Sublime Text to the Sublime Merge licensing terms.17

2022–present

Stable builds 4142 (November 2022), 4151 (August 2023), 4166 (November 2023), 4180 (August 2024) and 4189 (December 2024) followed, each announced on the blog with a changelog.18 Build 4200, released on 21 May 2025, announced the phase-out of the Python 3.3 plugin environment, a plan to replace Python 3.8 with Python 3.13, a Python support lifecycle of roughly five years, and new minimum system requirements of macOS 10.13 and Windows 10.19 Development builds using Python 3.13 (build 4201 and later) were distributed through the Discord server from late 2025. In December 2025 the Package Control repositories were transferred from Will Bond to the company's GitHub organization (see Package Control). Build 4213, released on 21 September 2026, replaced the Python 3.8 plugin environment with Python 3.14 and disabled Python 3.3 by default.20

Staff

Sublime HQ has remained small. In September 2020 the company had seven employees: six engineers, including Jon Skinner, and one person responsible for sales and non-technical support. In November 2022, the team grew to eight members. As of April 2024, all employees, except one, work from the company's Sydney office. Employees are identified on the Discord server by a "Sublime HQ" role.

Business model and licensing

Sublime Text can be evaluated without a time limit; an unregistered copy periodically displays a purchase reminder. Until version 4, a license key was tied to a major version, and upgrading from one major version to the next required a paid upgrade.56 The company has stated that this model required features to be held back for major releases, and that a one-time purchase could not fund ongoing development across the eight years in which version 3 was current.

Sublime Merge launched in 2018 with a different model, which Sublime Text 4 adopted in 2021: a license is perpetual and includes all updates released within three years of purchase. After that period, builds released within the window remain usable, and newer builds require purchasing an upgrade.1217 Sublime Text 3 licenses bought within three years of the Sublime Text 4 release were treated as valid for Sublime Text 4. At launch, upgrades for older licenses were offered at a reduced price of US$70 for a limited period before returning to US$80. The company sells separate personal and business licenses, and bundles of both products. The company has stated that it does not intend to adopt a subscription model for personal licenses.

Communication practices

The company does not publish a roadmap for Sublime Text. The company has explained that a roadmap would amount to a commitment to deliver specific features in a specific order, which it does not wish to make. An exception was a Sublime Merge roadmap post in October 2018, and the Sublime Merge 2 announcement listed planned future work.1314

Official announcements are made through the blog, which carried two posts between January 2025 and November 2026.1 Development builds, early-access programs and most direct interaction between staff and users take place on the official Discord server and the support forum, with bug reports and feature requests directed to the public GitHub issue trackers. Between 2017 and 2021 Skinner personally announced most development builds on the Discord server.

Views of the founder

Jon Skinner has expressed the following views on software design and on Sublime Text in public discussion with users:

  • Blinking carets waste power, battery life and energy for no benefit, and should be phased out. Sublime Text 4 uses a solid caret by default.
  • Syntax definition format: he regrets using YAML for .sublime-syntax files. He would prefer a small dedicated format with literal regular expressions and its own syntax highlighting. He considers generic data formats such as JSON, YAML and XML poorly suited to complex definitions, because regular expressions have to be encoded as strings.
  • Bundled snippets are mostly triggered by accident during auto-complete; he favours removing most of them, though doing so reduces discoverability.
  • Python is not his preferred language; the Python layer exists for extensibility, while the core is written in C++.
  • API stability: new APIs should not be added in patch releases. Some early API decisions are mistakes that can no longer be changed without breaking plugins. Backwards compatibility for existing plugins took priority in the move to Sublime Text 4.
  • Major versions: with licenses no longer tied to major versions, there is no reason for long beta periods like that of Sublime Text 3.
  • Asynchronous UI: results that change while a user is selecting from them make for a poor interface, so late auto-complete results are discarded instead of reordering a visible list.
  • Git interfaces: interactive rebase should be offered through direct manipulation of commits, not by recreating the command-line to-do list. Reviewing staged changes before committing is central to the Sublime Merge commit workflow.
  • Paid customization: restricting visual customization of Sublime Merge, such as the dark theme, to licensed users is reasonable.
  • Antivirus software often behaves much like malware. It is a frequent cause of bug reports that are not caused by the editor itself.
  • Platform vendors: Apple's notarization requirements and the Apple Silicon transition imposed significant changes on the company's build process.
  • Publicity: early development builds were kept within the Discord community, not promoted publicly, while they stabilized.

Products

Sublime Text

Sublime Text is written in C++ with a custom cross-platform user interface toolkit, and uses Python for plugins and much of its bundled functionality.3 Language support is provided by syntax definitions, originally in the TextMate .tmLanguage format and later in the editor's own YAML-based .sublime-syntax format. These are processed by a custom regular expression engine, with Oniguruma as a fallback. Features introduced over its history include multiple selections, the Goto Anything file and symbol navigator, the command palette, the minimap, distraction-free mode, project-wide symbol indexing, hardware-accelerated rendering and, in version 4, a solid (non-blinking) caret by default, which staff described as a power-saving measure.116

Plugins originally ran on Python 3.3, an embedded interpreter retained for backward compatibility. Sublime Text 4 added Python 3.8, with plugins opting in via a .python-version file. Build 4200 began the removal of Python 3.3, and build 4213 replaced 3.8 with 3.14 and disabled 3.3 by default.171920 The company stated that Python 3.3 could not be built for Apple Silicon, which affected the timing of native macOS ARM support. It also stated that running three Python environments side by side would not be sustainable.

Sublime Merge

Sublime Merge is a graphical Git client. It reads repository data with its own implementation, while operations that modify a repository are performed by invoking Git itself.12 It shares the user interface toolkit, text control, file system layer and preferences system with Sublime Text, and the two products are developed in the same internal repository. The evaluation version is fully functional except that it is limited to the light theme.12

Notable releases include build 1105 (March 2019), which allowed Sublime Merge to be used as a standalone three-way merge tool, and Sublime Merge 2 (May 2020). Sublime Merge 2 added repository tabs, a redesigned commit interface, configurable layouts, OpenGL rendering, commit signing and Git LFS support.1415 The Sublime Merge 2 announcement listed a review workflow, image diffs and plugin support as future work.14 Builds 2125 and 2136 were released in 2026.22

Ecosystem

Default packages

The syntax definitions, settings and supporting files bundled with Sublime Text are developed in the public sublimehq/Packages repository on GitHub, which accepts community contributions. During the Sublime Text 3 development period the bundled language definitions were progressively converted to the .sublime-syntax format and standardized on common scope naming conventions. Sublime Text 4 added syntax engine features such as branch_point backtracking and a version 2 syntax format. In August 2021 the company proposed giving a group of trusted community members write access, with pull requests requiring two approvals; the arrangement was put in place that month. Additions in later builds include a rewritten Lisp syntax (build 4180) and TOML and Zsh syntaxes (build 4200).1819

A company engineer also developed SBNF, an open-source grammar language that compiles to .sublime-syntax files, first released in February 2020.

Package Control

Package Control is the most widely used package manager for Sublime Text. Will Bond created it in 2011 as an independent project and continued to operate it after joining Sublime HQ in 2016.8 It consists of the client package installed in the editor, the packagecontrol.io website and crawler, a signing key for the client, and the default channel repository that lists available packages. Submissions to the default channel are reviewed by volunteers before inclusion. Recurring technical issues included the client's dependence on Python 3.3, which affected TLS support on newer systems; crawler failures caused by GitHub API rate limits; and the absence of a process for removing abandoned packages.

Language Server Protocol support

The Language Server Protocol (LSP) lets an editor obtain language features such as completions, diagnostics, go-to-definition, find references, renaming, formatting, code actions, hover documentation and inlay hints from an external language server. Sublime Text does not include a built-in LSP client. In July 2020 the company stated that it had considered native support but decided instead to extend the plugin API, because many language servers require server-specific workarounds. As a result, LSP-based language intelligence in Sublime Text is provided entirely by community-maintained packages. The project's Discord channel, opened in November 2019, became one of the most active channels on the server.

History. The LSP package was created by the GitHub user tomv564 while Sublime Text 3 was current. The ST3 API limited it: there was no support for asynchronous completions or for applying edits computed by a server against an earlier version of a document. On 21 December 2019, with version 0.9.3, the project moved to the sublimelsp GitHub organization, and maintenance passed to a group of volunteers. Sublime Text 4 development builds added APIs that the maintainers had asked for and tested: asynchronous completion lists, text-change events for incremental document synchronization, View.change_id() and View.transform_region_from() (build 4069, March 2020), and completion flags such as COMPLETION_FLAG_KEEP_PREFIX and INHIBIT_REORDER. In March 2020 the maintainers created the lsp_utils library, which downloads and manages language servers (for example via Node.js), so that individual servers could be shipped as preconfigured LSP-* packages. In 2020 the package stopped adding features for Sublime Text 3, and version 1.0 targeted Sublime Text 4. By 2024 more than 60 LSP-* packages had been published, covering languages including TypeScript, Python, PHP, Rust, Go, C/C++, Java, XML, JSON, Vue, CSS, HTML and ESLint. Later work tracked new protocol versions (3.16 and 3.17, including semantic tokens and inlay hints) and the migration to the Python 3.13 and 3.14 plugin environments.

Source code availability

Sublime Text and Sublime Merge are proprietary, and the company has stated that it has no plans to release their source code. In a December 2020 forum reply, a company employee wrote that doing so would remove the company's only viable business model. The reply also stated that support-based revenue models are not suited to offline developer tools, and that the codebase's complexity limits the benefit of outside contributions.21 In 2025 the company further stated that public source code would allow redistribution by Linux distributions and in-house builds by large organizations, and that a source-available license would be difficult to enforce internationally. The official documentation is maintained in the same private repository as the application; the API reference is generated from the bundled sublime.py and sublime_plugin.py modules. The default packages, Package Control and a community-maintained documentation site are open source.

Community relations

The company's main points of contact with users are the support forum, the official Discord server and the public GitHub issue trackers for Sublime Text and Sublime Merge. Company employees answer questions in these channels; feature requests and bug reports are directed to the issue trackers, which the company uses to track ongoing work.21 The table below summarizes frequently raised concerns and the responses given by the company or its employees.

No public roadmapA roadmap would amount to a promise to deliver features in a particular order, which the company does not want to make; a list of planned features would also do little to promote the product. Editors with public roadmaps are typically funded by large companies with marketing budgets.
